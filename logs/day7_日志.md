### "跑通 fingerprint-conditioned graph denoising"
1.任务理解
>把DAY5的加噪过程和DAY6的解码器变成一个整体，形成一个完整的训练流程。
fingerprint_conditioned说明每一条边的特征里面都带上了整张分子的指纹。“以指纹为条件”是说解码器在工作的时候不仅要看当前这条边的噪声状态，而且就还要看整个分子的指纹给出的**全局信息**。

**eg:**
>第1步：取一个干净的邻接矩阵 A0
>第2步：随机选一个时间步 t（比如 t=137）
>第3步：用 q_sample 把 A0 加噪到第 137 步 → 得到脏的 At
>第4步：用 build_init_feature 把 At 拆成一条条边特征
>第5步：把边特征喂给 edge_denoiser（MLP）→ 输出预测的键类型
>第6步：把预测和真实的 A0 对比 → 算交叉熵损失
>第7步：反向传播，更新MLP的参数
#### 训练最终要达到的目的
在前面的代码中，把At逐步还原成A0的最终输出是给一个五种键的概率分布列表，每一个位置的概率代表了这个位置每一种键的可能性，而概率最大的位置就是模型预测的这个位置的键的类型。
我们训练要达到的最终目的就是：**希望每一次A0中记录的真实的键的类型和模型预测得到的概率分布列表里面最大概率对应的键的类型是一致的**。
那么为了记录这个模型不断学习的过程，衡量这个模型自学习的效果，就需要一个指标来进行比较，这个指标就是交叉熵损失。
#### 自学习的过程
1.我们需要一个A0_label来记录A0的每一行是什么键。
A0_label记录的就是为1的那个位置的索引值。
2.这个索引值用来告诉模型去取哪一个位置的概率进行交叉熵的运算。
3.如果算出来的损失值很大，模型会因此调整参数，让下一次这个位置的损失值减小，也就是增大这个键出现的概率。
4.模型通过反向传播，逐步修改权重，让“正确答案”对应的概率逐渐变成概率列表中的最大值。
循环这个过程，这就是机器模型的自学习过程。
#### 交叉熵损失
>是预测模型预测出的数据和真实的数据之间的差值。
**交叉熵本质上是对模型预测正确答案成功概率的二次运算，成功的概率越高，交叉熵越低，损失越小**
---
计算这个交叉熵损失用的是PyTorch库里面的nn.CrossEntropyLoss函数。

### "小batch overfit"（小批量过拟合）
用极少量的数据（这里我用的是五个分子）训练模型，让模型记住这个样本，直到loss降至为0.
这只是一个测试，用来验证代码是否存在bug。
| 如果 overfit 成功 | 如果 overfit 失败 |
| :---: | :---: |
| loss 降到接近 0 | loss 降不下去，卡在某个值 |
| 说明模型能正常学习 | 说明模型、数据流或损失函数有问题 |

### "保存 checkpoint"
1.理解checkpoint
它保存的是模型的所有权重参数；保存它是为了防止训练结果丢失，防止每一次运行代码都要从最初始的状态开始而丢失了学习成果的情况。
**eg：**
>**没有checkpoint的情况**
第1次运行：loss 1.6 → 1.2 → 0.8 → 0.5（训练100轮，关机）
第2次运行：loss 1.6 → 1.2 → 0.8 → 0.5（从头开始，浪费昨天的时间）
>**有checkpoint**
第1次运行：loss 1.6 → 1.2 → 0.8 → 0.5（训练100轮，保存模型）
第2次运行：加载模型 → 从 0.5 继续 → 0.3 → 0.1 → 0.05（接着昨天的进度）
